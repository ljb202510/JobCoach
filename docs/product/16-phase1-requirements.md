## 1. 范围与上游

本文是 JobCoach 扩展的**第 1 期正式需求规格**，用于按 [dev-workflow.md](../plan/dev-workflow.md) 阶段 1~3 执行。第 1 期只做三块「产品基座」：

- **FR-12 账户与注册登录**
- **FR-13 我的简历模块**（模板 / 上传解析 / 保存 / 下载 / 预览）
- **FR-14 持久化与数据生命周期**（保存岗位 / 经历 / 计划，恢复 / 查询 / 删除）

第 1 期**明确不含**：证据溯源与来源标注（E1）、任务审阅（E2）、评测基准（E4）、RAG（E6）、短练习（E5）、渠道切换（E8）、可观测性（E10），以及管理员角色、忘记密码/重置。这些属第 2 期或后续，规格见 [15-consensus-requirements.md](15-consensus-requirements.md) §4。

## 4. 功能需求条目

### FR-12 账户与注册登录

**用户故事**：作为求职者，我希望注册并登录自己的账号，使我的简历、保存的岗位与准备计划只与我相关，不被他人看到。

**目标**：用户名+密码即可注册（无邮箱/手机验证），登录后数据按账户隔离；未登录仍可使用现有一次性分析链路。

**行为与验收**

| 场景 | 预期结果 | 当前状态 |
|---|---|---|
| 合法注册 | 用户名+密码非空且唯一，确认后创建用户，密码只存哈希；返回成功 | 待实现 |
| 用户名已存在 | 返回冲突错误（如 409），不覆盖既有账户 | 待实现 |
| 空/超长字段 | 返回 400 `INPUT_INVALID`，界面保留输入 | 待实现 |
| 登录 | 凭据正确进入登录态；错误返回 401，且不泄露「用户名是否存在」 | 待实现 |
| 数据隔离 | A 账户看不到 B 账户的简历/岗位/计划 | 待实现 |
| 游客模式 | 未登录仍可 `POST /api/matches` 一次性分析，不强制登录 | 保留现有链路 |

**边界**：不做邮箱/手机验证、不做忘记密码/重置、不做管理员与权限分级、不做第三方登录。

### FR-13 我的简历模块

**用户故事**：作为求职者，我希望上传简历文件（拖拽 / 选文件 / 读取本地文件夹）并让系统解析，保存为「我的简历」，可预览、下载、删除，从而省去手工粘贴。

**目标**：把「经历」的主要输入从手工粘贴改为文件上传与解析，并持久化为可复用的简历资产。

**行为与验收**

| 场景 | 预期结果 | 当前状态 |
|---|---|---|
| 上传 | 支持 `.pdf` / `.docx` / `.txt`，拖拽或文件选择或本地文件夹读取；前端显示上传中 | 待实现 |
| 解析 | 解析出文本并展示；解析失败 → 明确报错并回退手工粘贴，不产生半成品简历 | 待实现 |
| 保存 | 解析结果 + 原文件落盘；用户可持有多份简历 | 待实现 |
| 预览 | 网页内预览解析后文本 | 待实现 |
| 下载 | 原格式（PDF/Word）与 Markdown 均可下载 | 待实现 |
| 删除 | 删除后原文件与解析文本不可再查 | 待实现 |
| 红线 | 超大/损坏文件明确报错不崩溃；解析文本与原文件不写入日志 | 待实现 |

**边界**：模板暂为内置固定几套（不自定义/在线设计）；不做简历在线编辑器，只做上传→解析→展示→导出。

### FR-14 持久化与数据生命周期

**用户故事**：作为求职者，我希望把一次分析产生的岗位、经历、报告与准备计划保存下来，并在之后打开继续跟进，服务重启数据不丢。

**目标**：在无副作用的预览之上，增加「用户确认后的持久化」，并保证幂等、隔离与可删。

**行为与验收**

| 场景 | 预期结果 | 当前状态 |
|---|---|---|
| 保存岗位/经历 | 默认存结构化结果；原文由用户勾选是否一并保存 | 待实现 |
| 保存计划 | 用户确认后（draft→confirmed→saved）才落库；未确认不触发持久化 | 待实现 |
| 查询/恢复 | 按账户列出已保存的岗位、经历、报告、计划；重启后仍在（MySQL 待接入） | 待实现 |
| 删除 | 删除后不可查；删除账户/简历时级联清理关联数据 | 待实现 |
| 幂等 | 同一来源报告与幂等键不重复创建相同计划 | 待实现 |
| 红线 | 日志只含脱敏摘要；失败不留下「已保存」假状态；崩溃不丢已确认数据 | 待实现 |

**边界**：不做跨用户共享、不做全文检索、不引入异步执行与状态轮询（除非明确需要）。

## 5. 领域模型增量（草案）

在 [05-domain-model.md](05-domain-model.md) 基础上新增，仍是设计草案、非已批准 schema：

```text
User
  id
  username (唯一)
  passwordHash        # 只存哈希，永不明文/不落日志
  createdAt

Resume（我的简历）
  id
  userId -> User
  fileName            # 原文件名
  fileStoragePath     # 原文件落盘路径
  parsedText          # 解析文本（敏感，限制日志/保留）
  sourceFormat        # PDF / WORD / TXT
  createdAt / updatedAt

SavedJob（保存岗位）
  id
  userId -> User
  title
  structured          # 结构化岗位要求（默认保存）
  rawText             # 原文（用户勾选才保存，敏感）
  createdAt

SavedProfile（保存经历）
  id
  userId -> User
  structured          # 结构化经历/证据（默认保存）
  rawText             # 原文（勾选才保存，敏感）
  createdAt

MatchSession / PreparationPlan
  落地为持久化实体；PreparationPlan 沿用 draft -> confirmed -> saved，
  只有 confirmed 才写入，见 05-domain-model.md 生命周期。
```

**生命周期与不变量**

- `User.username` 全局唯一；`passwordHash` 永不返回给前端、不写日志。
- `Resume.parsedText`、`SavedJob.rawText`、`SavedProfile.rawText` 为敏感字段，日志只允许脱敏摘要；删除后级联清理原文件。
- `PreparationPlan` 未 `confirmed` 不落库；同一来源报告 + 幂等键不重复建计划。

## 6. API 契约增量（草案）

沿用 [06-api-contract.md](06-api-contract.md) 的错误体（`code`/`message`/`path`/`timestamp`）与「副作用必须有明确用户动作」约定。以下为契约草案，阶段 3 锁定：

| 端点 | 用途 | 关键校验 / 错误 |
|---|---|---|
| `POST /api/auth/register` | 注册 `{username,password}` | 唯一；空/超长→400 `INPUT_INVALID`；冲突→409 `USER_TAKEN` |
| `POST /api/auth/login` | 登录 | 正确→200；凭据错→401 `AUTH_INVALID`（不泄露用户名是否存在） |
| `GET /api/me/resumes` | 列出我的简历 | 需登录态 |
| `POST /api/me/resumes` | 上传 + 解析（multipart） | 支持 pdf/docx/txt；解析失败→明确 4xx 并可回退 |
| `GET /api/me/resumes/{id}` | 预览（解析文本） | 归属校验 |
| `GET /api/me/resumes/{id}/download` | 下载原文件 / Markdown | 归属校验；`format` 参数 |
| `DELETE /api/me/resumes/{id}` | 删除简历 | 级联清理原文件 |
| `POST /api/me/saved-jobs` | 保存岗位 `{structured, rawText?}` | rawText 仅勾选时提交 |
| `GET /api/me/saved-jobs` / `DELETE .../{id}` | 查询/删除保存岗位 | 归属校验 |
| `POST /api/me/saved-profiles` + 查询/删除 | 保存经历 | 同上 |
| `POST /api/matches/{id}/preparation-plan` | 用户确认后保存计划（继承 06 候选接口） | 携带来源报告 + 幂等键 |

**契约不变量**：响应不返回 `passwordHash` 与敏感原文；错误不泄露密钥/上游敏感头；可重试错误保留用户输入；保存类接口必须由用户动作触发，不能由页面加载或模型自动触发。

## 7. 非功能与红线

- **隐私**：`resume.parsedText`、岗位/经历原文、密码均为敏感数据；日志只记脱敏摘要；不把完整简历/岗位全文写入日志。
- **安全**：密码只存哈希；接口按账户做归属校验，防止越权访问他人数据。
- **幂等与一致**：保存接口幂等；删除级联；失败不留假状态；崩溃不丢已 `confirmed` 数据。
- **边界**：不自动抓取外部招聘平台（公理 5）；渠道切换若引入 Fake 降级必须显式标示，禁止静默把 Fake 当真实结果（见 [07-error-model.md](07-error-model.md) 约定）。

## 8. 验收证据与顺序

1. 领域对象先用 Java record / 内存对象验证状态与不变量（沿用 05 的实施顺序）。
2. Fake / mock 层建立后补 API 测试：注册冲突、登录失败不泄露、上传解析失败回退、删除级联、幂等防重复。
3. 前端构建 + 浏览器演示：拖拽上传、预览、下载、保存、查询、删除、重试/错误链路。
4. 隐私策略确认后再映射 MySQL 表、索引、级联删除与保留策略，用集成测试验证迁移与 Repository。
5. 只有实际运行且通过的场景标为「已验证」；未接入 MySQL 前，持久化相关场景保持「待验证」。
