# 上下文准备

## 上下文组成

目标、使用场景、现有实现、限制、目标文件、失败证据、验收方式和不可触碰事项。

## 控制上下文

优先给相关接口、类型、测试和调用方；说明文件路径但要求先验证文件存在。避免重复粘贴大段无关材料。

## 风险

上下文过少会导致猜测；上下文过多会稀释目标或混入过时信息。标注哪些是权威事实、哪些是待验证假设。

## 详细步骤

1. 先写一句用户目标和一句非目标，避免把“改善体验”当成可执行任务。
2. 收集相关入口、类型、测试、配置、最近错误和现有行为；过滤无关目录。
3. 为每条约束写来源：用户、源码、测试、官方文档或假设。
4. 给 AI 一个最小上下文包，并要求它先复述理解、列未知和提出 3-6 条计划。
5. 人工检查它是否漏掉失败状态、权限、隐私、回滚或已有未提交改动。
6. 计划确认后再修改；上下文发现冲突时先更新计划，不要静默选择一个假设。

## 输出模板

```text
目标：
现状证据：
允许修改：
禁止修改/非目标：
成功与失败验收：
未知与验证方式：
```
