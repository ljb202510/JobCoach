# AI 辅助需求拆解

## 步骤

把用户目标转成用户故事、主流程、正常/异常状态、非目标、验收标准，再分成可独立验证任务。

## 人工确认点

业务事实和范围由用户确认；技术方案可以由 AI 提供候选。不要把生成的需求细节当作用户已经批准。

## JobCoach 示例

核心任务先限定岗位描述 + 个人经历 -> 匹配报告；保存任务、文件上传、模拟面试作为单独增量，不混入第一条链路。

## 详细拆解步骤

1. 把用户请求改写成一个可观察行为：“用户提交两段文本后看到结构化报告”。
2. 列正常路径、空/超长输入、依赖失败、非法输出、重复请求和恢复动作。
3. 写非目标和暂缓项，尤其是登录、爬虫、向量库、多 Agent 和生产部署。
4. 为每个状态写验收：页面文本、HTTP code、响应字段、执行记录或测试断言。
5. 按依赖排序为探索、契约、业务、适配器、持久化、UI、验证任务。
6. 每个子任务控制在一两个相关测试可验证的范围；超过范围继续拆分。

## 拆解质量检查

- 是否有“完成”却没有可观察结果？
- 是否把技术实现误写成用户需求？
- 是否把多个副作用塞进一次任务？
- 是否明确哪个步骤需要用户确认？
