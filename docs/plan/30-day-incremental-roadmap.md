# 30 天增量路线

五天 MVP 不持久化，先完成 Fake 前后端闭环。MySQL、报告/计划保存、历史查询和数据保留策略从本路线开始：不持久化交付快且隐私/迁移负担小，但服务重启后没有历史；持久化可支持历史、恢复和审计，同时需要 schema、迁移、事务、失败处理、删除/保留策略和隐私评审。

| 周期 | 交付 | 验收证据 |
|---|---|---|
| 第 1 周 | 真实模型普通文本和结构化输出探测；固定 gateway 接口 | 实验记录、脱敏日志、解析单测 |
| 第 2 周 | MySQL/Flyway 接入会话、报告、执行记录；删除策略 | 集成测试、迁移脚本、隐私评审 |
| 第 3 周 | 准备计划 Tool 的白名单、确认步骤和任务状态 API | 工具参数测试、HTTP 契约测试 |
| 第 4 周 | 质量评测、错误重试、README/简历/面试材料迭代 | 最小评测集结果、演示录屏、diff review |

每周只扩大一个行为边界；若模型能力或数据库环境未验证，保持 Fake 链路可运行，不用计划替代证据。

## 每周执行模板

### 周一：定义边界

写本周唯一行为目标、非目标、风险、所需环境和验收样例；更新 `PROJECT_GOALS.md` 对应阶段。

### 周二：最小实现/实验

先用 fake 或无副作用夹具跑通路径，再接真实依赖。每次只改变一个变量，保存命令、输入摘要和结果类别。

### 周三：失败与安全

主动测试超时、非法结构、权限、重复调用、敏感日志、回滚和恢复；失败不通过吞异常或跳过断言解决。

### 周四：集成与 Review

运行单测、API/集成测试、构建和手工演示；逐文件检查 diff、依赖、配置和文档是否同步。

### 周五：证据与复盘

更新状态矩阵、技术决策、README、简历材料和下周入口。明确“已验证/用户确认/待验证/暂缓”，删除无证据的宣传句。

## 30 天门禁

- 每周只允许一个主行为扩大；第二个行为必须进入候选列表而不是偷偷实现。
- 环境不可用时先做 fake/契约测试，不以“以后会安装”作为验收。
- 真实模型和数据库实验必须脱敏，密钥只在环境变量中出现。
- 每周末可从当前提交恢复并重跑最小演示；不能恢复的实验不算完成。
