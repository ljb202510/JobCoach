# JobCoach 功能需求规格

## 功能地图

| 功能点 | 用户价值 | 阶段 |
|---|---|---|
| 岗位与经历文本输入 | 快速提交分析材料 | 已有 Fake 链路；本轮继续验收 |
| LLM 匹配分析与报告 | 看清岗位要求、经历证据和技能差距 | 本轮 P0；真实模型待验证 |
| 准备计划生成与预览 | 把差距转成可检查的具体任务 | 本轮增加无副作用预览；保存仍是下一增量 |
| 计划确认与保存 | 重新打开后继续跟进任务 | 预览质量验证后再做；需用户确认和持久化 |
| RAG 资料检索 | 让建议引用可信资料 | 后续独立增量，先确认资料来源和效果 |
| 模拟面试 | 围绕岗位与差距练习回答 | 后续独立增量 |
| 简历上传与解析、报告历史、登录、岗位导入 | 减少输入成本或支持长期使用 | 候选功能，尚未排期 |

岗位导入目前只表示减少手工粘贴；是否支持链接或特定招聘平台尚未决定。任何抓取都需另行评估数据来源和平台约束。

## 本轮功能：生成匹配报告

### 用户与目标

面向准备 Java 后端或 AI 应用岗位的学生及初级求职者。用户粘贴岗位描述和个人经历后，应看到岗位要求、已有证据、证据不足处和下一步准备建议。匹配分仅作辅助参考，不代表录用概率。

用户故事：作为求职者，我希望提交目标岗位和自己的项目经历，获得可检查的匹配分析，以便决定先补充哪些经历证据和技能。

本轮目标：真实模型返回可解析的结构化匹配报告；模型不可用时可切换到 Fake 模式继续演示请求和页面链路。Fake 报告是固定夹具，不代表真实分析；当前没有请求失败后自动切换 Fake 的行为。

### P0 行为与验收

| 场景 | 预期结果 | 当前状态 |
|---|---|---|
| 合法输入 | 用户提交非空的岗位描述和个人经历；页面显示加载状态，成功后展示 0-100 匹配分、岗位要求、证据、技能差距、风险和建议 | Fake 链路已有测试和构建证据；真实模型待实测 |
| 空白或超长输入 | 后端拒绝空白字段和超过 20,000 字符的字段，返回 HTTP 400、`INPUT_INVALID`；页面保留输入供修改 | 空白输入有 API 测试；超长边界待补证据 |
| 非法 JSON 请求 | 后端返回 HTTP 400、`BODY_INVALID`，不生成报告 | 已有 API 测试 |
| 模型连接失败、上游错误或超时 | 页面不展示伪成功报告，保留输入并允许重试；后端返回稳定且不泄露敏感数据的错误 | 上游错误有通用映射；超时分类与真实行为待验证 |
| 模型返回非法结构 | 不展示报告；后端返回可识别的输出错误；缺字段、错误类型和分数越界均应被拒绝 | 分数越界有解析测试；其余边界待验证 |
| Fake 演示 | 无 Key、无外网时可提交并查看固定报告；用户能识别这是演示模式 | Fake API 已验证；浏览器演示待记录 |

输入和输出沿用现有 `POST /api/matches` 与 `MatchReport` 契约，详见 `06-api-contract.md`。真实模型请求只用脱敏样例验证，不把密钥、Authorization、完整简历或岗位全文写入日志。

### 本轮边界

- 不保存报告、简历、历史或准备任务；准备计划仅供预览，服务重启后无历史可查。
- 文件上传、岗位抓取、自动投递、登录、MySQL、RAG、模拟面试和有副作用的 Tool Calling 暂缓。
- 准备任务的保存和执行记录属于后续迭代，不能作为本轮成功验收的隐含前提。

### 验收证据

后端测试 `mvn test -q`、前端构建 `npm run build`、Fake 浏览器成功/错误/重试演示，以及真实模型脱敏实验记录。只有实际运行且通过的场景才标为“已验证”；缺少 API Key 时，真实模型相关场景保持“待验证”。
