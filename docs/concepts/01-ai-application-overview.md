# AI 应用全景

## 定义

AI 应用是围绕模型构建的软件系统。它通常还包含用户界面、业务逻辑、上下文构造、工具、数据、持久化、错误处理和评估，不等于一段 Prompt。

## 为什么存在

基础模型提供通用生成能力，但业务应用需要控制输入、权限、数据来源、结果结构、流程状态和失败行为。

## 最小链路

```text
用户输入 -> 校验 -> 上下文/Prompt -> 模型 -> 解析/校验 -> 业务动作 -> 展示/记录
```

## 概念边界

- 模型：生成或理解内容的组件。
- Prompt：一次调用中传给模型的指令和上下文。
- Tool：应用提供给模型选择调用的受控操作。
- Workflow：应用预先定义的步骤编排。
- Agent：在目标约束下根据观察决定下一步的循环系统。
- RAG：检索外部资料并将其加入模型上下文的一种模式。

## JobCoach 映射

岗位与个人经历是输入；匹配报告是模型辅助产生的结果；任务计划是业务数据；保存任务属于需要授权和校验的动作。

## 验证与局限

验证整条链路：无效输入应拒绝；模型失败应形成错误状态；不合法结构不得进入业务层；工具不得越权。模型输出仍可能遗漏、偏见或编造，匹配分数不是客观录用概率。

## 面试表达

说明 AI 应用除了模型调用，还必须把模型接进可验证的业务边界，并指出模型不是可信数据库或规则引擎。

## 学习步骤与最小实验

1. 在仓库中找到入口：前端表单、`MatchController`、应用服务、`AiGateway`、报告 DTO 和错误处理。
2. 画出一次请求的时序图，标记每一步的输入、输出、失败状态和是否可重试。
3. 用 fake gateway 返回合法报告、非法报告和异常，观察请求分别在哪里停止。
4. 检查日志和响应是否泄露完整岗位/经历、密钥或内部异常；记录一个需要脱敏的位置。
5. 把“模型生成内容”和“应用决定是否接受/保存”分开写在文档中。

实验验收：能用一个请求说明模型只负责候选分析，分数范围、证据要求、保存授权和错误状态由应用控制。

## 常见误区

- 把一段 Prompt 叫作完整 AI 应用，忽略校验、状态、权限和观测。
- 把模型回答直接写入数据库或驱动副作用。
- 用演示成功替代正常、边界、失败和回归验证。

## 复盘问题
