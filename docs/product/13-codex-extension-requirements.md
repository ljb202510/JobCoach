# Codex-JobCoach MVP 扩展需求建议（独立稿）

## 1. 目的与口径

本文是供后续 Trae、Qoder、Codex 交叉评审的 **Codex 独立提案**，不是三方共识或实施承诺。当前 MVP 已能提交岗位与经历文本、查看 Fake/Real 匹配报告及无副作用的准备计划预览；计划保存、历史、RAG、模拟面试等尚未成为产品能力。现状以 [实现边界](11-implementation-boundaries.md) 和实际验证记录为准。

本稿只定义用户问题、候选功能、验收和立项条件。接口、数据库表与技术选型留到选定单个增量之后设计。P1/P2 表示候选先后次序，不改写当前 MVP 的 P0 范围。

## 2. 从第一性原理推导

### 2.1 用户要完成的事

目标用户不是为了获得一份报告，而是要对一个岗位做出准备决策：

```text
理解岗位要求 → 核对自身证据 → 识别真正的缺口 → 选择可完成的任务 → 检查准备是否改善
```

由此得到四个判断标准：

1. **可信**：每项判断能回到用户输入或明确的通用规则；资料引用不能代替个人经历证据。
2. **可行动**：建议要有优先级、完成标准和合理工作量；更多建议不一定更有用。
3. **可恢复**：跨天使用时，用户能找回主动保存的计划，并能删除自己的数据。
4. **可验证**：产品改动应能通过脱敏样例、用户操作或对照实验发现改善与失败。

这些标准同时服务项目的 4:4:2 目标：可演示的求职准备闭环、可复核的 AI coding 过程，以及支撑闭环所需的 Java 后端能力。技术名词本身不构成立项理由。

### 2.2 当前缺口与证据级别

| 缺口 | 当前依据 | 尚待验证的假设 |
|---|---|---|
| 报告判断难以逐项核对 | 现有报告展示要求、证据和差距；规格未要求每项绑定原文位置 | 来源标注能提高用户信任和纠错效率 |
| 预览任务未形成执行反馈 | 已有无副作用计划预览；保存与状态跟进未实现 | 用户愿意审阅、调整并持续执行这些任务 |
| 跨天使用缺少恢复能力 | 当前无报告/计划持久化 | 跨天恢复比一次性报告更有价值 |
| 模型质量缺少持续业务判断 | 已有脱敏实验和最小样例，长期质量仍待观察 | 固定样例与人工复核能发现有意义的回归 |

## 3. 方向总览

| 编号 | 方向 | 建议级别 | 价值链位置 | 立项门槛 |
|---|---|---|---|---|
| C1 | 报告证据溯源与纠错 | P1 首选 | 核对自身证据 | 来源定位实验可行 |
| C2 | 准备任务审阅与可执行性验证 | P1 | 选择行动 | 任务质量经样例评审 |
| C3 | 用户确认后的保存、恢复与删除 | P1，有前置决策 | 跨天执行 | 数据隔离与保留规则确定 |
| C4 | 差距改善的前后对比 | P2 | 检查效果 | C1、C3 稳定且用户需要复盘 |
| C5 | 报告与计划的业务评测集 | P1 支撑项 | 贯穿分析与行动 | 脱敏样例和人工判定规则就绪 |
| C6 | 针对差距的短练习 | P2 | 执行行动 | 题目与反馈可核查 |
| C7 | 输入减负与资料引用 | 条件候选 | 输入、行动 | 观察到输入阻碍或检索收益 |

## 4. 功能规格

### C1 报告证据溯源与纠错（P1 首选）

- **用户故事**：作为求职者，我希望知道“符合”“不足”和“无法判断”分别依据哪段岗位与经历文本，以便纠正错误判断。
- **最小切片**：一份报告中，每条关键判断显示可定位的原文片段或“输入未提供相关证据”；用户修改经历后可重新分析。
- **验收**：脱敏样例覆盖明确具备、明确不具备、只缺证据三种情况；引用片段必须存在于输入；更正输入后结果独立生成且原输入仍可编辑；定位失败时显示证据不足，不伪造引用。
- **依赖与风险**：先验证结构化输出中的来源定位稳定性；引用岗位要求与引用个人经历要分开。分数变化不能被解释为录用概率。
- **权重归属**：作品集产品 4、AI coding 4；需要报告契约和校验，但不要求先建数据库。

### C2 准备任务审阅与可执行性验证（P1）

- **用户故事**：作为求职者，我希望先删改不适合自己的任务，再决定是否保留计划。
- **最小切片**：现有预览中支持调整一项任务的优先级或完成标准，并清楚保留它对应的差距；本切片仍不写库。
- **验收**：每项任务可回答“为什么做、做到什么算完成”；删除或修改任务不会改变原始报告；模型失败时已有预览与输入不丢失；用脱敏案例人工检查任务是否过于空泛或不合理。
- **依赖与风险**：需明确预览的数据结构和编辑边界。先验证用户是否真会修改任务，避免给无效任务增加保存能力。
- **权重归属**：作品集产品 4、AI coding 4。

### C3 用户确认后的保存、恢复与删除（P1，有前置决策）

- **用户故事**：作为求职者，我希望主动保存准备计划，第二天继续跟进，并能删除它。
- **最小切片**：一位明确隔离的使用者确认保存一份计划；查询、完成一项任务、删除；重启服务后状态仍可恢复。
- **验收**：预览和未确认状态不写库；重复确认不创建重复计划；删除后查询不到计划及其关联记录；失败不会留下“已保存”假状态；日志不含岗位或经历全文。
- **依赖与风险**：先决定本地单用户还是多用户、原文是否保存、保留时长、备份与删除边界；再做迁移、持久化和集成测试。不能在共享环境仅凭可猜测 ID 读取别人的数据。
- **权重归属**：作品集产品 4、Java 后端 2、受控工具行为的 AI coding 4。

### C4 差距改善的前后对比（P2）

- **用户故事**：作为求职者，我希望完成任务并补充成果后，知道哪些岗位要求有了新证据。
- **最小切片**：同一岗位的一项差距，记录用户新增的成果文本，重新分析后并排显示前后证据状态。
- **验收**：变化能指向新增的用户事实；未变化的项不宣称改善；历史结果保持原样可查；不以总分上涨代替证据变化。
- **依赖与风险**：依赖 C1 的逐项证据与 C3 的版本关联；先验证用户是否需要长期复盘。
- **权重归属**：作品集产品 4、AI coding 4。

### C5 报告与计划的业务评测集（P1 支撑项）

- **使用者故事**：作为开发者，我希望在更换提示词或模型后，知道报告是否少编造、计划是否更可执行。
- **最小切片**：复用现有脱敏样例，标注少量“证据正确性、证据不足识别、任务具体性”人工判定规则，并记录版本和失败类别。
- **验收**：同一组输入能对比两个版本；结构通过与业务正确分别统计；不能把关键词命中率当成完整的质量结论；记录不含密钥或真实简历。
- **依赖与风险**：需要人工复核样例，模型输出非确定性应记录重复运行结果。此项是开发质量门槛，不是面向求职者的新页面。
- **权重归属**：AI coding 4。

### C6 针对差距的短练习（P2）

- **用户故事**：作为求职者，我希望针对一项证据不足的技能做一道可回答的练习题，并得到具体反馈。
- **最小切片**：选定一项差距，生成一道题和评价标准，用户提交文本回答后展示引用该回答的反馈。
- **验收**：题目对应岗位要求；反馈指出回答中的具体内容和遗漏，不虚构未说过的经历；失败可重试。只有短练习有用，才评估多轮模拟面试。
- **依赖与风险**：需评价规则与人工样例；对话历史和语音不进入最小切片。
- **权重归属**：作品集产品 4、AI coding 4。

### C7 输入减负与资料引用（条件候选）

- **输入减负**：先测量用户粘贴经历的耗时与错误；若确有阻碍，先支持本地纯文本读取、预览和编辑确认，解析失败回到手工输入。PDF/Word、链接导入和网站抓取分别评审数据与平台约束。
- **资料引用**：先选一项差距和可信资料源，比较有检索与无检索建议的正确性、可执行性和引用准确性；只有改善稳定时才加入产品链路。资料引用不能证明用户具备某项技能。
- **边界**：两者都不应成为 C1-C3 的隐含依赖；RAG、向量库和自动抓取不按技术展示价值直接排期。
- **权重归属**：输入减负服务作品集产品 4；检索对照服务 AI coding 4。

## 5. 顺序、取舍与待评审问题

**建议下一轮只选择 C1**：它直接改善当前报告的可信度，能在不持久化个人资料的前提下验证。C5 的少量判定样例可作为 C1 的验收准备。随后用 C2 验证预览是否值得保存；C3 要等隐私与身份边界明确后实施。C4、C6、C7 依据使用反馈分别立项，不预设都要做。

暂不建议自动投递、录用概率预测、自主多 Agent 执行、任意工具调用或通用招聘网站抓取。这些方向没有当前主链路的必要性证据，且增加外部副作用或真实性风险。模型渠道切换和流式展示可作为独立工程候选，但应在可用性数据表明其优先于 C1-C3 时再安排。

交叉评审需要回答：

1. C1 的来源引用是否可在当前报告结构中稳定定位？失败时如何呈现？
2. 用户是否愿意编辑预览任务，哪些任务算“可执行”？
3. 是否长期保存岗位/经历原文？使用范围是本机单用户还是共享多用户？
4. 现有评测样例能否发现编造证据与空泛建议，需补哪些人工判定案例？

评审时请分别记录 Trae、Qoder、Codex 对每项方向的支持、修改或反对意见及证据，再更新共识规格；本文在此之前始终是独立稿。
