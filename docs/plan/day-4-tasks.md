# 第 4 天：前端联调、RAG 评估和端到端敏捷迭代

预计 6-8 小时。本天把前三天的后端、Fake/真实 AI 和工具边界接到 Vue，按真实用户路径完成整体联调，再评估 RAG 是否值得纳入 MVP。

## 本天迭代目标

用户可以打开页面，提交岗位与经历，看到匹配报告和错误状态；准备任务保存只做后续路线设计，不在五天 MVP 产生持久化副作用；RAG 只在对比实验证明有收益时进入下一轮。

## 阅读与学习清单（约 90 分钟）

### 必读项目文档

- `docs/product/08-demo-script.md`：学习成功演示、失败演示和 Fake 模式说明。
- `docs/product/04-non-functional-requirements.md`：学习安全、可测试、可诊断、可复现和隐私要求。
- `docs/concepts/07-rag.md`：学习数据准备、切分、检索、上下文、生成和引用验证。
- `docs/concepts/08-memory-and-state.md`：学习页面状态、Agent 状态、业务持久化和敏感数据保留的区别。
- `docs/concepts/10-ai-application-testing.md`：学习单元、API、模型实验、工具和端到端测试的分层。
- `docs/ai-coding/05-incremental-implementation.md`、`08-diff-review.md`：学习前端联调中的小步实现和 Review 顺序。

### 必读代码与测试

- `frontend/src/App.vue`：学习表单、加载、成功和错误状态如何映射到用户流程。
- `frontend/src/api/client.ts`：学习 API 请求、错误转换和类型边界。
- `frontend/src/api/types.ts`：学习前后端响应契约如何在前端表达。
- `frontend/vite.config.ts`：学习开发代理如何把 `/api` 请求转给后端。
- `frontend/src/styles.css`：检查长文本、移动端布局和错误提示是否支持真实演示。

### 今天必须掌握的概念

RAG、Memory/State、端到端测试和用户可观察状态。重点回答：检索内容如何进入 Prompt，如何处理无命中和冲突资料，为什么页面不能把模型失败显示成成功。

### 阅读后的输出

先画页面状态机，再写一张 RAG 对照表：数据来源、切分、查询、Top-K、无命中行为、引用验证、延迟和是否纳入 MVP。没有基线对照，不把 RAG 写成已提升质量。

## 固定 AI coding 循环

```text
评审 API/AI backlog -> 拆前端状态和联调任务 -> 页面/API 修改
-> 构建与端到端验证 -> RAG 对照实验 -> Review
-> 修复回归 -> 更新 MVP 状态和下一轮 backlog
```

## 步骤

### 1. 评审联调目标（45 分钟）

1. 阅读 Day 3 的 API、错误、工具和模型状态记录。
2. 明确本轮用户路径：输入 → 提交 → 加载 → 报告 → 退出或进入后续准备任务 backlog。
3. 列出页面状态、接口状态和错误 code 的映射。
4. 选择必须修复的 P0 问题，视觉优化和历史记录放入 backlog。

### 2. 拆分前端任务（45 分钟）

拆成 API client 类型、输入表单、加载状态、报告展示、错误恢复和端到端验证；准备任务确认只记录接口设计，不在当前 Fake 闭环执行保存。每项指定组件/文件、接口、验收和回滚点。

### 3. 实现并联调（120 分钟）

1. API client 统一处理 URL、请求类型、响应类型和错误转换。
2. 页面支持初始、编辑、提交中、成功、空输入、后端失败、模型失败和重试。
3. 报告按结论、证据、差距、建议和任务展示，不只展示一个分数。
4. 若展示准备任务预览，必须出现用户确认动作；当前页面不自动保存，也不跨重启保留数据。
5. 启动前后端，提交正常样例并检查浏览器请求、HTTP 响应、日志和页面状态。

### 4. 故障联调和回归（75 分钟）

逐个制造并记录：空输入、超长输入、后端停止、模型超时、非法报告、重复点击、工具失败。每次确认输入是否保留、提示是否可理解、重试是否安全。

### 5. RAG 对照实验（75 分钟）

1. 选小型公开技能资料，记录来源和版本。
2. 先做关键词检索基线，再做 Embedding 或其他检索候选。
3. 使用相同岗位问题比较无检索/有检索的证据覆盖、引用正确性、延迟和无命中行为。
4. 如果不能稳定提升报告质量，就保留实验结果并把 RAG 放入下一轮 backlog。

### 6. Review 和敏捷收尾（45 分钟）

1. 运行 `mvn test -q`、`npm run build`、端到端手工演示和 `git diff --check`。
2. 让 Codex Review API 类型、UI 状态、错误恢复、隐私和工具确认。
3. 修复高优先级问题，再重新走一次完整用户路径。
4. 更新实现边界：哪些已经端到端验证，哪些只是局部实验。

## 本天交付

- Vue 与后端完整联调
- 成功、加载、错误和重试状态；准备任务确认作为后续路线设计记录
- 一次完整端到端演示
- RAG 基线对照实验
- 前后端 Review 和下一轮 backlog

## 本天验收

- 用户可以完成一次可理解的匹配分析。
- `mvn test -q` 和 `npm run build` 通过。
- 失败状态不会被页面伪装成成功。
- 能解释 RAG 是否改善了什么，以及为什么纳入或暂缓。

## 复盘

1. 哪个问题只有整体联调才发现？
2. 页面展示是否让用户理解了证据不足和模型不确定性？
3. 当前 MVP 最影响用户价值的缺口是什么？
