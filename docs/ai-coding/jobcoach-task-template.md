## Codex 请求模板

```text
先阅读 docs/plan/PROJECT_GOALS.md 和以下文件：<paths>。
目标：<one behavior>。
约束：保持现有架构，不引入密钥/网络调用/无关重构。
先报告事实、假设和 3-6 条计划；修改前说明文件范围。
分小步实现，每步运行最快相关测试；失败时引用实际错误并修复。
最后给出文件、测试命令、结果、风险和未完成项。
```

## Review 模板

- 行为：成功、加载、空、错误、重试是否都可验证？
- 契约：请求、响应、状态码和错误码是否一致？
- 安全：是否泄露 key、原文、日志敏感信息？
- 边界：空值、超长、非法 JSON、重复提交、超时？
- 测试：是否有最小回归测试，是否真正走 HTTP？
- 范围：是否出现未授权重构或伪造指标？

## 调试请求模板

```text
现象：<exact symptom>
复现命令：<command>
实际输出：<error excerpt>
已知事实：<facts>
请先列 2-3 个可证伪假设，再设计最小实验；只修改确认根因所需的文件。
```

## 测试生成模板

```text
围绕 <class/endpoint> 生成测试：正常、空输入、非法输入、依赖异常、边界长度。
优先使用现有测试框架和夹具；HTTP 接口必须断言状态码、错误码和关键响应字段。
不要测试实现细节，不要引入真实网络或密钥。
```
