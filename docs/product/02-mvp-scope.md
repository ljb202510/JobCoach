# JobCoach MVP 范围

## P0

- 岗位描述 + 简历/经历文本输入。
- 结构化匹配报告，包含要求、证据、差距、风险/不确定性和建议。
- 用户可查看结果；准备任务保存属于后续阶段。
- Fake 模式下保留受控业务动作的端口设计，但五天 MVP 不执行持久化副作用。
- 当前请求内的执行状态可展示，跨请求历史和执行记录属于后续阶段。
- Vue 页面、后端测试、启动文档和可复现演示。

## 暂缓

- 文件上传/解析、岗位爬取、自动投递。
- 登录和多人资料隔离。
- 多 Agent、自由规划、模拟面试。
- 向量数据库、Redis、流式 UI。

## 取舍规则

任何增加的功能都必须说明它服务作品集 4、AI/Codex 4 或 Java 后端 2 中哪一项，以及会挤占什么时间。

## MVP 分阶段实施

### P0-A：可测试主链路

输入校验、Fake gateway、结构化报告、统一错误、Vue 成功/加载/错误状态和 README 演示必须先完成。此阶段不依赖真实模型、MySQL 或 Docker，也不持久化用户输入或报告。

### P0-B：受控业务动作

在后续路线中增加用户确认和准备任务保存接口；先用内存/fake 记录工具执行状态，再接入 MySQL。五天 MVP 只保留接口边界和演示所需的非持久化状态。

### P0-C：真实能力替换

单独探测文本、结构化和工具能力；真实 adapter 不能破坏 Fake 回归集。能力未验证时保留降级路径。

## MVP 退出标准

- 正常路径和至少三类失败路径有自动测试或可重复演示。
- 关键行为有 API、前端、应用层和文档证据。
- P1/P2 没有混入 P0 的隐式依赖。
- README 能说明运行前提、fake/真实差异和当前局限。
- 五天 MVP 明确说明服务重启后不保留历史；MySQL 和持久化进入后续 30 天路线。
