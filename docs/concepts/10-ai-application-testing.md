# AI 应用测试

## 测试层

- 纯业务单元测试：fake gateway，验证领域和编排逻辑。
- API 测试：请求校验、响应结构和错误状态。
- Prompt/模型实验：真实模型能力和输出质量，单独运行、记录版本。
- 工具测试：白名单、参数、权限、幂等和失败。
- 端到端演示：真实或可控 fake 模式下完整用户路径。

## 为什么不能只断言文本完全相等

模型输出存在非确定性。关注 Schema 合法性、关键事实、有证据支持、拒答行为、工具安全和回归集指标。

## 局限

少量测试不等于模型可靠；离线评测和线上行为也可能不同。每个评测结论必须标注模型、提示词和数据版本。

## 测试设计步骤

1. 先写可观察行为，而不是先写“模型应该聪明”：输入边界、字段契约、证据要求、拒答和工具权限。
2. 用 fake gateway 覆盖确定性业务规则，再为真实模型建立小而稳定的评测集。
3. 为每条评测样例记录输入版本、Prompt 版本、模型、期望属性、实际结果和人工判定。
4. 将结构合法性、语义事实、引用支持、拒答质量、延迟和成本分别统计，不合并成一个神秘总分。
5. 每次 Prompt、模型或检索器变化都运行回归集；发现退化时保留旧结果做对照。
6. 对工具和持久化做幂等、权限、超时、重试、部分失败和审计测试。

## 最小评测表

| 类别 | 示例问题 | 通过标准 |
|---|---|---|
| 输入校验 | 空岗位/经历 | 稳定错误，不调用模型 |
| 结构 | 缺少差距字段 | 拒绝或受控修复，不进入领域层 |
| 事实 | 经历没有某技能 | 不得生成无证据掌握结论 |
| 工具 | 重复保存同一任务 | 幂等或明确拒绝 |
| 故障 | 模型超时 | 状态可见，可重试，不伪造成功 |

## 复盘问题

1. 哪些测试能在没有真实模型时完成？哪些必须实测？
2. 模型输出退化时，先回滚模型、Prompt、检索还是业务规则？证据是什么？
3. 线上用户反馈如何进入离线评测集，同时保护隐私？
