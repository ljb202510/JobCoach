# 前置资产准备计划

## 目的

在用户暂时离开、不方便频繁确认时，完成低风险、可复用、不会改变核心产品边界的准备工作。目标是让后续用户或多个 Agent 可以快速开始，而不是替用户做未确认的产品决策。

## 可直接完成

1. 概念知识文档：定义、边界、验证和局限。
2. AI coding 全流程手册和任务模板。
3. JobCoach 产品规格草案，明确已确认内容与待确认项。
4. 版本兼容性、模型能力探测和依赖决策模板。
5. 后端/前端目录骨架、README、运行/测试入口。
6. 多 Agent 委派规范、状态矩阵和变更记录模板。
7. 使用 fake gateway 的可重复单元测试。

## 暂不自动完成

- 不猜测未确认的产品字段、用户流程或隐私策略。
- 不再擅自安装或修改 Docker/MySQL；使用用户已准备好的 MySQL 8.4.9 作为环境事实，持久化接入仍需单独计划和验证。
- 不使用或索取 API Key，不执行真实模型请求。
- 不把 LangChain4j、Spring AI、MyBatis-Plus 版本假设写成最终事实。
- 不添加岗位爬虫、登录、多 Agent、向量数据库等 P1/P2 功能。

## 资产完成标准

- 文档可导航，计划、产品、工程、概念、AI coding、复盘分目录。
- 每项事实有状态：已验证、用户确认、待验证、草案或暂缓。
- 代码骨架能构建，fake 模式测试通过。
- 后续只需要用户少量确认即可进入真实模型实验和主流程开发。

## 资产分层与验收步骤

### 1. 目标层

确认 `PROJECT_GOALS.md`、4:4:2 权重、P0/P1/P2 和用户流程一致；发现冲突时先更新目标基准，不在下游文档各自解释。

### 2. 学习层

每篇概念文档都有定义、边界、JobCoach 映射、最小实验、失败与复盘问题；未执行实验必须保留待验证状态。

### 3. 工程层

后端/前端骨架可构建，fake 链路有测试，环境变量示例不含密钥，依赖选择有官方核验入口，数据库草案不冒充已迁移。

### 4. 协作层

任务模板包含上下文、范围、禁止项、验收、回报格式；多个 Agent 或模型不会同时修改同一所有权文件。

### 5. 交接层

后续 Agent 先读目标和状态矩阵，再读任务相关文档；接手时能找到下一步命令、已知失败和需要用户确认的问题。

## 低风险工作的详细顺序

1. 先盘点文件和链接，不创建与现有导航冲突的第二套入口。
2. 先扩写规则、模板和实验计划，再生成代码骨架。
3. 每次生成后运行文档链接、路径、命令和敏感信息检查。
4. 将发现写入 `findings.md`，将动作和命令写入 `progress.md`，将长期决策写入目标/决策文档。
5. 任何需要用户拍板的字段、隐私期限、权限模型或外部服务，停在待确认表，不自行定案。
