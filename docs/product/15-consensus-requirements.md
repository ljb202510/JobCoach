## 3. TRAE 评审结论（编排/隐私/证据视角）

对 13（Codex）与 14（Qoder）的裁决要点：

- **认同 C1/Q2 证据溯源为 P1 首选**：直接落下公理 4（可信度），不需要持久化与隐私决策，是唯一零阻塞的用户可见 P1。
- **认同 C2「任务审阅先于保存」**：审阅质量应先于落库；否则「保存」建成的是伪闭环。
- **认同 C3/Q1/Q4 持久化以 D14 隐私决策为前置**：身份隔离、原文是否保存、保留时长、删除边界未定前不能建表。（该前置已被用户拍板部分解决，见 §2.3 与 §6。）
- **评测定位**：Q3/D6/C5 是支撑项而非用户功能，不作为独立增量，本次并入证据溯源验收。
- **红线复核**：D2 岗位抓取、D5 静默降级 Fake（会伪成功）、D11 外部推送、Q8 工具链副作用，均需显式闸门，本文已在 §4 标注。

## 4. 最终方向池与分级

### P1

**E0 账户与注册登录**（新增，用户拍板 #3）
- 一句话：用户名 + 密码注册/登录，确认即注册，不做邮箱/手机验证；作为数据隔离的前提。
- 验收点：注册后可登录；数据按账户隔离；密码不明文存储（哈希）；未登录仍可使用一次性分析（游客/演示模式保留）。
- 依赖/前置：E3 持久化；用户名唯一性；密码找回暂缓（见 §6）。
- 权重：作品集产品 4 / Java 后端 2（认证与安全）。

**ER 我的简历模块（含文件上传解析）**（新增，用户拍板）
- 一句话：提供内置简历模板、文件上传（拖拽/选文件/访问本地文件夹读取）、解析、保存、下载、预览，作为「经历」的主要输入来源，并持久化。
- 验收点：拖拽/选文件上传 PDF/Word/txt 并解析；解析失败回退手工粘贴；可保存为「我的简历」供复用；可预览/下载，下载格式 PDF/Word/Markdown 均支持；模板暂用内置固定几套；**简历原文件落盘保存**（供下次预览/下载）；解析与文件处理不入日志敏感原文。
- 依赖/前置：E0 账户（简历归属）、E3 持久化（文件/文本存储）、文件解析库选型。
- 权重：作品集产品 4 / Java 后端 2（文件 I/O、格式解析）。**取代原 E7 的「文件解析」定位；岗位链接导入仍候选。**

**E1 证据溯源与来源标注**（合并自 C1、Q2）
- 一句话：报告每项「符合/不足/无法判断」可定位到岗位或经历的原文片段，失败时显示「证据不足」而非伪造引用。
- 验收点：引用片段必须存在于输入；更正输入后可重分析；定位失败不伪造；引用岗位要求与引用个人经历分开。
- 依赖/前置：结构化输出增加来源定位，无持久化依赖；本次 Q3 最小规则并入其验收。
- 权重：作品集产品 4 / AI coding 4（结构化输出＋校验）。

**E2 准备任务审阅与可执行性验证**（合并自 C2）
- 一句话：用户先删改不适合的任务、明确完成标准，再决定是否保存；本切片仍不落库。
- 验收点：每任务能回答「为什么做、做到什么算完成」；修改任务不改原始报告；失败时预览与输入不丢。
- 依赖/前置：预览数据结构与编辑边界；验证用户是否真的会编辑。

**E3 持久化与数据生命周期**（合并自 D8+D12+D13+D14、C3、Q1+Q4；已按用户拍板定稿）
- 一句话：用户确认后保存**计划/岗位/经历/简历**，可恢复/查询/删除，重启不丢；多用户按账户隔离。
- 验收点：未确认不落库；幂等；删除后不可查；失败不留下「已保存」假状态；日志无岗位/经历/简历全文；「保存岗位/经历」默认存结构化结果，**原文由用户勾选是否一并保存**；简历原文件落盘。
- 依赖/前置：E0 账户；再做迁移、Repository、集成测试。

**E4 评测基准框架**（合并自 D6、C5、Q3；本轮并入 E1 验收，不单独立项）
- 一句话：固定脱敏样例 + 人工判定规则，比较模型/prompt 变更前后的业务正确性。
- 验收点：结构通过与业务正确分开统计；模型非确定性需记录重复运行；不以关键词命中率当质量结论。
- 依赖/前置：现有脱敏样例可复用。

### P2

**E5 针对差距的短练习**（合并自 D9、C6，多轮模拟面试 D10 后置）
- 一句话：针对一项证据不足生成一道题，用户提交文本回答后得到引用其回答的反馈。
- 验收点：题目对应岗位要求；反馈指出具体内容与遗漏、不虚构经历；失败可重试；先单轮，再评估多轮。

**E6 RAG 可信资料检索**（合并自 D4、Q5、C7 引用部分；用户拍板 #4：来源开放）
- 一句话：为差距建议附可核查资料来源，先关键词检索、向量库后置；资料来源不限类别，以可信 + 可回溯为准。
- 验收点：引用可回溯；有 RAG vs 无 RAG 对照、效果优于基线；资料引用不能证明用户具备技能。

**E8 多模型渠道切换与降级**（合并自 D5、Q9）
- 一句话：主渠道失效切备选或降级；**显式标示当前模式，禁止静默把 Fake 当真实结果返回**。
- 验收点：切换对用户透明或有明确提示；每渠道独立验证结构化/工具/流式能力。

**E9 差距改善前后对比**（合并自 C4）
- 一句话：用户补充成果后重新分析，并排显示前后证据状态。
- 验收点：变化能指向新增用户事实；未变项不宣称改善;历史结果可查；不以总分上涨代替证据变化。

**E10 可观测性与成本记录**（合并自 D18、Q10）
- 一句话：记录每次调用耗时、失败类别与成本（脱敏），先最小指标，不加额外遥测网络调用。
- 验收点：每次调用可解释耗时与失败原因；成本可统计；不记敏感原文。

### 候选

- **C-岗位链接导入**（D2）：来源合法性审查前不抓取。
- **C-流式输出**（D7，仅 Trae 提出）：先测 20s+ 等待痛点与流式能力，再与结构化报告取舍。
- **C-历史输入复用**（D3）：浏览器本地缓存可低成本解决，需先定义敏感经历的清除规则。
- **C-Agent 式多轮对话**（Q6）：先验证静态解释是否不足，再定义可判定错误率。

### 剔除（当前路线）

- **多 Agent 产品能力**（D15）、**Workflow→受限 Agent 升级**（D17）：无「动态决策优于固定流程」的用户结果证据，有对照收益时重新评审。
- **工具编排扩展**（Q8/D16 独立立项）：无独立用户任务；保留「白名单＋参数校验＋审计」作为各功能落地的硬约束。
- **任务提醒/推送**（D11）：依赖外部通知与定时，无用户需求不接。

## 5. 裁决：分期（已按用户确认）

三元评审原裁决「下一轮只做 E1」，但用户新增的 **E0 账户 + ER 我的简历 + E3 持久化** 构成远大于单增量的「产品基座」块，经用户确认按下面两期拆分：

- **第 1 期（产品基座）**：E0 账户 → ER 我的简历（上传/解析/预览/下载）→ E3 持久化（含岗位/经历/简历保存）。理由：账户 + 持久化是后续一切长期功能（历史、隔离、简历复用）的前置地基。
- **第 2 期（可信度与闭环）**：E1 证据溯源（含 E4 最小评测）→ E2 任务审阅 → E3 计划保存跟进。理由：补强报告可信度与「审阅 → 保存 → 跟进」闭环。

E1 不依赖账户/持久化，必要时可提前或与第 1 期并行，由用户后续调度。
