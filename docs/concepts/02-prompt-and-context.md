# Prompt 与上下文

## 定义与作用

Prompt 是给模型的任务指令；上下文是模型当前可见的输入信息，可能包含系统约束、用户内容、检索结果、历史消息和工具结果。

## 实用结构

```text
角色/目标 + 输入数据 + 约束 + 输出格式 + 不确定时的处理 + 示例（必要时）
```

## 边界

Prompt 不是权限系统。写着“不得访问文件”不能替代应用层根本不暴露文件工具。上下文不是长期记忆，超出上下文窗口的信息模型无法可靠使用。

## JobCoach 用法

明确区分岗位原文和候选人经历；要求报告逐项给出证据；无证据时输出“未提供”，不得推断候选人具备该技能。

## 验证与局限

用同一输入改变提示词，比较结构稳定性、遗漏和无证据断言。Prompt 版本需要测试；增加文字不必然增加可靠性。

## 面试表达

解释如何把目标、数据、约束和输出契约写清楚，并指出提示词只能引导模型，不能代替代码校验。

## 学习步骤与最小实验

1. 为 JobCoach 写一版最小 Prompt，只包含目标、岗位原文、经历原文、证据规则和输出字段。
2. 复制同一输入，分别删除约束、删除证据要求、改变输出格式，比较遗漏、猜测和结构漂移。
3. 将岗位文本、经历文本、系统规则和检索资料用清晰标签分隔，观察模型是否混淆来源。
4. 添加“资料不足时输出未提供，不得推断”的约束，并用没有某项技能的样例验证。
5. 给 Prompt 加版本号，记录模型、输入样例、输出问题和改动原因；不要只保存最终文本。

实验验收：至少有一组对照结果，能说明哪条提示词约束改善了什么，也能说明它没有解决什么。

## 常见误区

- 认为 Prompt 中写了“禁止访问”就等于权限控制。
- 无限制拼接历史消息，导致上下文过长、冲突或隐私扩大。
- 用模糊的“请分析得专业一些”替代可观察的输出契约。

## 复盘问题

1. 哪些信息属于系统规则，哪些属于用户数据，哪些属于不可信检索内容？
2. 如果上下文超过窗口，优先保留哪些信息，丢弃哪些信息？
3. Prompt 变更如何进入回归集，而不是靠一次手工感觉？
