# 项目探索与上下文建立

## 要达到的结果

在改代码之前形成简明项目地图：入口、模块、数据流、配置、测试、构建命令、未提交改动和风险。

## Codex 操作

要求 Codex 只读探索：列出相关文件、证据引用、既有约定和未知项，不允许修改。自己抽查关键源文件和 `git status`。

## 验收

能说明本次任务的真实入口与最小影响范围；所有结论能在仓库找到证据。

## 详细步骤

1. 先运行 `git status --short`，记录已有改动，避免把用户工作当成任务产物。
2. 用 `rg --files` 找入口、配置、测试、迁移、README 和相关文档；不要凭文件名猜路径。
3. 从 API/用户动作反向追调用方和被调用方，画出最小数据流。
4. 阅读相邻实现和测试，记录命名、错误、日志、依赖和构建约定。
5. 把发现分成事实、推断、未知，并为每个未知写最小验证动作。
6. 输出“允许修改/禁止修改/非目标/验收命令”，再进入下一阶段。

## 常见失败

- 只列目录不读入口代码；
- 只看成功测试不看错误路径；
- 把旧文档或归档方向当成当前产品目标。
