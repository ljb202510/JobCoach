# 数据保留与隐私说明（草案）

JobCoach 输入包含岗位描述和个人经历，可能包含姓名、联系方式、公司和项目细节。当前 fake 模式不持久化数据；数据库草案也不会自动执行。

## 最小规则

- 默认只保存完成演示或用户明确确认的分析会话。
- 原始文本与结构化报告暂定保存 30 天，过期删除；执行记录只保留脱敏摘要和错误类别 90 天。
- 日志不得记录原始简历、岗位全文、API Key、Authorization 或模型原始敏感响应。
- 导出、删除和审计操作必须按 `session_id` 定位，避免按全文搜索。
- 真实模型请求前，提示用户不要输入身份证号、银行卡号、账号密码等无关敏感信息。

## 落地前检查

1. 明确是否需要账号隔离，以及删除请求的认证边界。
2. 确认 MySQL 备份、日志和模型供应商的保留期限与地域。
3. 用集成测试验证会话、报告、计划和任务的级联删除策略。
4. 评估是否需要字段级加密；密钥只能来自部署环境的密钥管理系统。

这些是设计约束，不是已完成的合规结论。
