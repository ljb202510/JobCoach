# Agent、工具和 RAG

Agent loop：读取目标 → 生成下一步 → 判断是否需要工具 → 校验参数 → 执行工具 → 记录结果 → 继续或结束。

第一版只允许 `saveTaskPlan`，不允许访问文件系统、执行 Shell 或修改代码。工具输入必须有 DTO 和校验，执行前后写步骤记录。

后续 RAG 流程：问题 → 检索项目规则 → 拼接上下文 → 生成 → 验证。第一版先不依赖向量数据库。

## 设计与实现步骤

1. 先写 Agent 的目标、可观察状态、工具白名单、预算和停止条件。
2. 明确哪些步骤固定为 Workflow，哪些步骤才允许模型选择。
3. 为每个工具定义 DTO、权限、幂等、超时、审计和失败返回；不暴露任意 Shell/SQL/文件系统。
4. 先用 fake 工具和固定结果测试循环，再接真实 provider 或持久化。
5. 保存每轮输入摘要、决策、工具结果、状态变化和停止原因，注意脱敏。
6. 用成功、工具失败、超时、预算耗尽、用户拒绝和重启恢复样例验证。

## JobCoach 最小边界

第一版可把“分析 → 报告 → 用户确认 → 保存计划”实现为固定 Workflow。只有当系统需要根据报告缺口选择技能检索或追问时，才增加受限 Agent；增加后必须证明它带来用户价值，而不只是增加模型调用次数。
