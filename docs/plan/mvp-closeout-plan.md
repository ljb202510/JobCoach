# JobCoach MVP 收口计划

本文件是 `dev-workflow.md` 的一次实例，也是当前唯一在执行的计划。它不是从今天起算的 20 小时倒计时——前面的 Fake 闭环、前端、基础测试已经完成。这里只列剩下的收尾工作，按阶段顺序把"待验证"一项项关成"已验证"。

## 当前基线

已验证：

- 后端骨架、`POST /api/matches`、输入校验、统一错误、健康检查；本轮扩展到 8 个测试类 22 个用例，`mvn test -q` 通过。
- `RealAiGateway` 已用 Spring `RestClient` 完整实现，`RealAiGatewayTest` 已覆盖 fence 解析、超范围分数、缺字段、上游 503、超时 504。
- 前端单文件 `App.vue` 状态机（idle/loading/success/error）、30 秒超时、重试，`npm run build` 通过。
- Qwen3.5 单样本结构化报告（你提供的截图，B 级证据）。

本轮已收口：

- 真实模型的普通文本、结构化、异常、多样本系统探测。
- Tool Calling 受控工具的真实实现与白名单校验：加入无副作用的准备计划预览，不执行持久化或外部副作用。
- 前端在浏览器里的加载、失败、重试、窄屏、长文本。
- Skill 流程试运行、MCP 只读/浏览器验证、Code Review、全量回归、README 演示、简历证据、7 个概念与 Codex 能力的证据。

仍待后续观察：真实模型长期稳定性、自然产生的非法结构，以及产品级 RAG 的资料来源和效果。它们不作为本轮交付的隐含前提。

暂缓（不进本轮）：

- MySQL 持久化、LangChain4j 引入、RAG 向量库、登录、文件上传、岗位抓取、模拟面试、产品级多 Agent。

## 收口目标

把 JobCoach 收口成一条真实模型驱动、可回退 Fake、四类状态可验证的可演示 MVP，同时补齐 7 个概念与 Codex 能力的证据。

## 收口清单

做完一项勾一项，全部勾上即交付：

- [x] 真实模型普通、结构化、至少一类失败、多样本，有脱敏记录（失败为真实超时；非法结构仅有模拟测试）
- [x] `PreparationPlanTool` 有白名单与无副作用的准备计划预览，并有真实 Tool Calling 证据
- [x] 输入错、模型错、超时、非法结构有稳定行为并有测试
- [x] 前端浏览器加载、成功、失败、重试四态有证据；Real 成功路径有证据（失败/重试为受控 502 模拟）
- [x] `mvn test -q`、`npm run build`、`git diff --check` 通过
- [x] 至少一次项目级 Skill 试运行和一次 MCP 只读验证，有可复查记录
- [x] 盘点并实际使用至少一个已安装的通用 Skill，记录选择理由、使用结果和对开发的帮助
- [x] 7 个概念 + Codex 五项能力各有一条 A/B 证据（概念学习证据；产品 RAG 仍暂缓）
- [x] README、演示脚本、简历、下一步 backlog 齐备

## 执行分工

本轮 MVP 收口只使用 Codex，Codex 负责实现、测试、浏览器联调、Review、证据和文档。后续增量开发可参考 `dev-workflow.md` 再启用多 agent。

以下表格仅供后续增量开发参考，不用于本轮：

| 工具 | 职责范围 |
|---|---|
| Codex | 后端全部：真实模型探测、`PreparationPlanTool`、错误硬化、单元测试、`/review`、git 与回归 |
| Qoder | 需求评审、方案与接口契约、前端实现、后端交叉复核 |
| TRAE | 上下文与编排、浏览器联调、Skill / MCP / RAG 证据、README / 简历 / 演示 |

## 阶段顺序

对应 `dev-workflow.md` 的十个阶段，每阶段有主执行、复核和完成判据。

| 阶段 | 本轮动作 | 主执行 | 复核 | 完成判据 |
|---|---|---|---|---|
| 0 上下文与基线 | 读流程、目标、状态；跑三条命令 | Codex | 用户 | 一句话目标 + 三命令结果 |
| 1 需求评审 | 正常、输入错、模型错三类用户故事 + 非目标 | Codex | 用户 | P0 都有可验证验收 |
| 2 优先级排序 | 定 P0/P1/P2，其余进 backlog | Codex | 用户 | P0 不含 P1/P2 隐含依赖 |
| 3 方案与接口 | 冻结契约 + Workflow/Agent 取舍 | Codex | 用户 | 契约先于代码改动 |
| 4 实现 | 真实探测 + 受控工具 + 错误硬化 | Codex | Codex 自查 | 实测记录 + 白名单测试 |
| 5 单元测试 | 四类用例，`mvn test -q` 通过 | Codex | Codex 自查 | 全绿 + 修复过程有记录 |
| 6 整体联调 | 前端四态 + 浏览器 Fake/Real | Codex | 用户 | Fake 与 Real 各自有证据 |
| 7 Code Review | 契约、异常、脱敏、依赖、文档同步 | Codex | Codex 自查 | 至少一个取舍 + 一个发现 |
| 8 修复与回归 | 只修最高优先级，跑回归 | Codex | Codex 自查 | 修复前后证据或"无问题"结论 |
| 9 交付与复盘 | Skill/MCP/RAG 证据 + 演示、简历、backlog | Codex | 用户 | 概念证据 + 交付物齐备 |

## 执行规则

本文件是当前唯一在执行的收口计划。按阶段顺序推进，每阶段结束把目标、概念、动作、文件、命令结果、问题、下一步写入 `docs/ai-coding/collaboration-record.md`。没有实际证据的项保持"待验证"。每轮走完 10 个阶段，不跳评审、不跳测试、不跳 Review。

每阶段回报格式：

```text
阶段：
目标：
概念绑定：
需求/优先级决定：
修改或实验：
文件：
命令与结果：
Review 发现：
未解决风险：
下一阶段动作：
```
