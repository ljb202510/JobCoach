# JobCoach 功能需求草案

## FR-1 输入资料

用户可输入岗位描述和个人简历/项目经历文本。两字段必填，长度上限由 API 契约统一定义。

## FR-2 生成匹配报告

报告列出岗位要求及重要度、用户经历证据、匹配状态、技能差距、风险/不确定性和准备建议。缺少证据时必须表达“不足以判断”，不能编造经历。

## FR-3 准备任务（后续路线）

用户可从报告生成任务计划。每项任务包含目标、优先级、建议完成条件；保存操作需由用户显式触发。

## FR-4 执行记录（后续路线）

应用记录请求状态、模型步骤、工具调用和错误摘要，不记录密钥。

## FR-5 结果查看

界面提供输入、加载、成功和错误状态。五天 MVP 不提供跨重启历史；历史记录在 MySQL 持久化接入后再验收。

## 功能验收用例

### FR-1 输入资料

- 正常：两字段均有内容，提交按钮可用。
- 边界：全空格、超长、前端绕过校验的请求都被后端拒绝。
- 隐私：界面提示不要输入身份证号、银行卡号和密码等无关敏感信息。

### FR-2 匹配报告

- 正常：每项要求有状态、证据或“证据不足”。
- 失败：模型超时/非法结构不进入成功状态，记录错误类别。
- 质量：分数（若最终保留）不能替代逐项证据和不确定性。

### FR-3 准备任务

- 生成前必须展示任务预览或确认动作。
- 每项任务包含目标、优先级、完成条件和来源报告。
- 重复确认不会重复创建相同任务。

### FR-4 执行记录

- 记录阶段、状态、耗时、错误类别和脱敏摘要。
- 不记录密钥、Authorization、完整原始简历和不必要的岗位全文。

## 需求优先级判定

新功能只有同时说明用户动作、可观察结果、失败恢复和验证方式，才能进入 P0；只增加模型“自由度”但没有用户价值的需求进入暂缓。
