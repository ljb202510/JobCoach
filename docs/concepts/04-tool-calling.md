# Tool Calling

## 定义

模型在响应中提出一个结构化工具调用请求；应用验证该请求并决定是否执行，再把结果交还模型或业务流程。

## 调用流程

```text
提供工具描述 -> 模型选择工具/参数 -> 应用校验授权 -> 执行 -> 记录 -> 处理结果
```

模型通常不直接执行 Java 方法。真正调用发生在宿主应用。

## 安全边界

- 工具白名单；最小权限；输入校验；超时；幂等策略；审计记录。
- 不把任意 Shell、文件系统或 SQL 暴露给模型。
- 用户需确认的副作用操作应有明确确认步骤。

## JobCoach 用法

`savePreparationPlan` 只允许保存当前分析生成的准备任务，不能自行更改简历或投递岗位。

## 验证与局限

测试未知工具名、缺字段、超长参数、重复调用、拒绝授权和工具超时。模型可能提出错误或诱导性调用；描述清晰也不代替权限控制。

## 学习步骤与最小实验

1. 先声明一个无副作用工具，明确名称、输入 DTO、返回结构、超时和失败状态。
2. 构造合法调用、未知工具、缺字段、越权 userId、重复幂等键和超时样例。
3. 在应用层依次执行白名单、参数、资源归属、用户确认和幂等校验，再进入适配器。
4. 为每次调用记录 requested、validated、executed、failed 或 rejected，避免只记录最终文本。
5. 将工具返回结果作为不可信数据再次校验，不允许模型通过返回内容改变权限或工具集合。

实验验收：工具即使收到恶意或错误参数，也只能影响允许的当前报告/任务，且状态可追踪、可重放或可解释地拒绝。

## 常见误区

- 把任意 Shell、SQL 或文件系统能力直接暴露给模型。
- 只在 Prompt 中要求“谨慎”，没有代码级权限和资源归属检查。
- 忽略重复调用，导致重复任务、重复扣费或不可逆副作用。

2. 哪一步需要用户确认，确认结果如何持久化？
3. 工具执行超时后，如何判断是否已经产生副作用？
