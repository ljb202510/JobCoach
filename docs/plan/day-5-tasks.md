# 第 5 天：完整 MVP 的发布前迭代和敏捷复盘

预计 5-7 小时。本天不是单独包装材料，而是把前四天累计的 JobCoach 当成一个待交付产品，执行一次发布前迭代：整体 Review、回归、修复、联调复查、文档同步和下一轮规划。

## 本天迭代目标

确认 JobCoach MVP 能被陌生人启动和演示，核心行为有测试和证据，AI coding 过程可回放，未完成能力和下一轮 backlog 清楚。

## 阅读与学习清单（约 75 分钟）

### 必读项目文档

- `docs/plan/PROJECT_GOALS.md`：重新核对主线、交付范围、证据等级和完成判据。
- `docs/product/09-resume-description.md`：学习如何只使用已验证事实写项目经历。
- `docs/product/10-technical-highlights.md`：学习如何从真实实现提炼技术亮点。
- `docs/product/11-implementation-boundaries.md`：学习区分已实现、未实现和当前局限。
- `docs/review/00-preflight-checklist.md`：学习发布前的完整检查顺序。
- `docs/review/11-interview-qa.md`：学习如何把开发证据转换成面试表达；每日复盘直接记录在本项目的 `progress.md`。

### 必读 AI coding 文档

- `docs/ai-coding/07-testing-and-verification.md`：学习长任务中的测试、CI、部署检查和人工确认。
- `docs/ai-coding/08-diff-review.md`：学习按需求、行为、数据、权限、错误和测试顺序 Review。
- `docs/ai-coding/10-personal-methodology.md`：学习如何从真实任务沉淀 Skill、模板和下一轮改进。
- `docs/ai-coding/12-ai-coding-session-record.md`：学习如何回放完整的需求、方案、实现、失败、测试和复盘证据。

### 今天必须掌握的概念

交付门禁、回归测试、Code Review、敏捷 backlog、Skill 复用和证据等级。重点回答：哪些内容已经证明，哪些只是模型建议，下一轮为什么优先做某一项。

### 阅读后的输出

完成一份发布前证据表：用户需求、代码位置、测试命令、演示步骤、已知风险和状态。再写一份下一轮 backlog，每项包含价值、优先级、依赖、验收和第一个探索动作。

## 固定 AI coding 循环

```text
发布前需求核对 -> 全量测试/构建 -> Code/Product/Security Review
-> 修复 P0/P1 -> 完整联调和演示 -> 文档同步
-> MVP 验收 -> 复盘 -> 30 天敏捷 backlog
```

## 步骤

### 1. 重新确认发布范围（30 分钟）

1. 阅读 `PROJECT_GOALS.md`、MVP 范围和实现边界。
2. 对照实际代码列出已实现、已验证、用户确认、待验证和暂缓。
3. 删除或标记没有证据的“已支持”描述。
4. 把本轮发布范围锁定为一个可复现的 MVP，不在最后一天临时增加大功能。

### 2. 从 README 重新启动（60 分钟）

1. 按 README 在新终端执行环境检查、后端测试/启动、前端安装/构建/启动。
2. 走成功路径和至少三条失败路径。
3. 记录端口、配置、依赖、错误提示和任何需要手工补充的步骤。
4. 修复 README、脚本、配置或错误提示中的真实问题，并重新验证。

### 3. 做三类 Review（90 分钟）

**需求 Review**：实现是否满足用户故事，P0 是否完整，是否混入未授权功能。

**代码 Review**：分层、错误、边界、重试、幂等、日志、依赖和无关 diff。

**产品/安全 Review**：页面是否可理解、模型状态是否透明、敏感信息是否泄露、工具是否需要确认。

让 Codex 提出问题，人工根据源码、测试和演示证据确认。每个问题按 P0/P1/P2 处理。

### 4. 全量回归和修复（90 分钟）

1. 运行后端 `mvn test -q`、前端 `npm run build`、`git diff --check`。
2. 运行 API/页面端到端路径：成功、输入错误、模型失败、工具失败、重试。
3. 修复高优先级问题后先跑局部测试，再跑全量测试。
4. 检查真实模型实验、Fake 模式和 RAG 实验记录是否与当前代码一致。

### 5. 同步文档和演示（45 分钟）

同步 README、API 契约、状态矩阵、实现边界、演示脚本、技术亮点和 AI coding 会话记录。演示中明确 Fake、真实模型和实验能力的区别。

### 6. 复盘并建立下一轮 backlog（45 分钟）

1. 回放需求评审、拆分、Plan、实现、测试、Review、联调和修复证据。
2. 记录 AI 找到的问题、AI 漏掉的问题和人工发现的问题。
3. 将重复流程沉淀成 Skill 或模板，将项目特定假设留在项目文档。
4. 按用户价值、风险、依赖和学习收益排列 30 天 backlog。
5. 为下一项任务写目标、非目标、验收和第一个探索命令。

## 本天交付

- 一个可启动、可演示的 JobCoach MVP
- 全量测试、构建、联调和 Review 证据
- README、API、状态矩阵和实现边界同步
- 完整 AI coding 会话记录
- 按优先级排列的下一轮敏捷 backlog

## 本天验收

- 陌生用户按 README 能启动 Fake MVP。
- 核心用户路径和失败路径都有证据。
- 能完整讲述从需求到联调的 AI coding 流程。
- 能说明 RAG、Skill、Tool Calling、MCP、Agent 在项目中的实际位置和限制。
- 不把未验证功能、模型性能或个人体验写成项目事实。

## 复盘

1. 哪一次 Review 或测试改变了原来的方案？
2. 哪个 AI coding 环节最能提升质量，哪个环节仍然薄弱？
3. 下一轮只允许做一个增量时，为什么选择它？
