# JobCoach 用户流程

## P0：岗位匹配与准备计划

1. 用户粘贴岗位描述。
2. 用户粘贴简历或项目经历文本。
3. 前端校验必填，后端统一校验长度，显示可编辑输入。
4. 用户提交；页面显示处理中状态。
5. 后端生成匹配报告：岗位要求、支持证据、未满足/证据不足项、建议。
6. 用户检查报告；准备计划保存属于后续阶段，当前 MVP 只展示分析结果。
7. 后续阶段由用户显式确认后保存计划，并显示执行结果。

## 失败状态

- 输入非法：前端/后端指出字段问题。
- 模型不可用或超时：保留输入，显示可重试错误。
- 输出结构无效：不保存为成功报告，记录可诊断失败。
- 保存任务失败（后续阶段）：展示报告仍可查看，允许在确认幂等后重试保存。

## 产品待确认项

匹配分数是否需要展示、用户资料是否保存、计划是否必须人工确认、报告历史是否属于 P0，须结合作品范围再决定。

## 详细状态流

```text
EMPTY -> EDITING -> VALIDATING -> ANALYZING -> REPORT_READY
                                      -> CONFIRMING_PLAN -> PLAN_SAVED
```

任一阶段都可能进入 `INPUT_INVALID`、`BODY_INVALID`、`MODEL_UNAVAILABLE`、`MODEL_TIMEOUT`、`OUTPUT_INVALID` 或 `TOOL_FAILED`；失败状态必须保留可恢复的上一步输入或报告。

## 每步验收

| 步骤 | 进入条件 | 成功结果 | 失败结果 |
|---|---|---|---|
| 输入 | 两段文本可编辑 | 前端和后端规则一致 | 指向字段的错误 |
| 分析 | 校验通过 | 有报告和执行状态 | 可重试，不保存伪报告 |
| 查看 | 报告校验通过 | 要求、证据、差距、建议可读 | 显示结构失败原因 |
| 保存（后续阶段） | 用户显式确认 | 任务计划和执行记录可查 | 报告仍可查看并重试 |

## 手工演示顺序

先走成功路径，再清空岗位字段、停止后端、制造模型/工具失败，最后刷新或重试确认状态是否符合预期。
